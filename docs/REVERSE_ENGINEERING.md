# 리버스 엔지니어링 노트

## 원본 실행 파일

| 항목 | 값 |
|---|---|
| 파일 | `시작.exe` (한국어판 배포본의 실행 파일, 135,168 바이트) |
| 형식 | PE32 GUI, i386, MSVC 6.0 링커, 빌드 시각 2004-02-11 |
| 창 클래스 / 제목 | `sotsuken` / `斬るビル` |
| 중복 실행 방지 뮤텍스 | `卒研２００３` |
| 사용 API | DDRAW(DirectDrawCreateEx), DSOUND, DirectMusic(COM), WINMM(timeGetTime, joyGetPosEx, mmio), GDI(TextOutA) |
| 코드 구성 | `0x401000-0x410690` 게임 로직, `0x410690-0x413f30` 엔진(WinMain·DirectX 래퍼·태스크), `0x413f34-` MSVC CRT(정적 링크) |

한국어판은 이미지만 한글화되어 있고 실행 파일 안의 문자열과 스토리 텍스트(`data/023.dat`,
`data/024.dat`, XOR 0x3A)는 일본어(Shift-JIS) 그대로입니다.

### Windows 11에서 원활하지 않은 이유

* `SetDisplayMode(640, 480, 8)` + 독점 전체화면: Windows 8 이후 8비트 팔레트 모드는 호환성
  에뮬레이션으로만 동작하고, 해상도 전환과 팔레트 처리에 문제가 생기기 쉽습니다.
* DirectMusic(`IDirectMusicPerformance`, `IDirectMusicLoader`)은 더 이상 유지되지 않는 API입니다.
  원본은 DirectSound·DirectMusic·DirectDraw 중 하나라도 초기화에 실패하면 오류창
  (`ダイレクト…の初期化に失敗！`)을 띄우고 종료합니다. Wine에서 실험했을 때도 오디오 장치가 없으면
  DirectSound, 3D 가속이 없으면 DirectDraw 단계에서 바로 종료됐습니다.

## 디컴파일 과정

1. angr 10.x로 CFG 복원(1003개 함수) 후 게임 영역 전체를 의사 C로 디컴파일 (`tools/decompile/`).
2. vtable(0x41c25c, 0x41c28c, 0x41c2bc, 0x41c31c…)을 덤프해 엔진 클래스 메서드를 식별.
3. 게임 로직 200개 함수(0x401000-0x410690)를 6개 구간으로 나눠, 디컴파일 결과를 objdump 어셈블리와 대조하면서 C++로 1:1 번역
   (`src/game/part_a..f.cpp`, 번역 규칙: `docs/TRANSLATION_CONVENTIONS.md`, 함수별 노트: `docs/notes/`).
4. 엔진 계층(DirectX 래퍼, 입력, 태스크 스케줄러)은 동작을 그대로 재현하는 새 구현으로 교체 (`src/engine/`).
5. 원본 리플레이 20개와 Wine에서 돌린 원본 화면으로 검증.

## 엔진 구조

### 태스크 스케줄러 (0x412770-0x412a30)

* 0x220 바이트 태스크 1024개를 정적 풀(0x4205d8)에 두고, 빈 슬롯은 링 버퍼(0x4a85d8)로 관리.
* 우선순위 오름차순 이중 연결 리스트 (헤드 -1, 꼬리 1000000).
* 생성(0x4128c0): 스택에 만든 0x220 바이트 디스크립터를 통째로 복사.
* 매 프레임(0x412870): `wait > 0`이면 1 감소, 콜백 호출, 그 뒤 `dead` 태스크 회수.
* 우선순위 값은 마스크로도 쓰임 (`0x4129b0(127)` = 우선순위 & 127인 태스크 정지 등).

```
+0x00 prio  +0x04 ?  +0x08 wait  +0x0c parent  +0x10 prev  +0x14 next
+0x18 dead  +0x1c callback  +0x20.. 사용자 데이터
```

### 그래픽 (객체 0x41fa98, vtable 0x41c28c)

* 640×480×8 주 화면 + 백버퍼 1장(Flip 시 내용이 교환됨), 오프스크린 서피스 최대 128개.
* `vtbl+0x0c` (0x411110): 화면 기준으로 직접 클리핑 후 `BltFast(SRCCOLORKEY)`.
  BltFast/Blt는 자체 클리핑이 없어 사각형이 서피스를 벗어나면 **아무것도 그리지 않음** → 그대로 재현.
* 모든 BMP는 `LoadImage` + `BitBlt`로 서피스에 복사 → GDI 최근접 색 매칭.
* 컬러키·채우기 색은 `SetPixel`/`GetPixel` 왕복으로 RGB→팔레트 인덱스 변환 (0x411410, 0x411d30).
* **핵심 발견**: 팔레트를 `DDPCAPS_8BIT`만으로 만들고 `DDPCAPS_ALLOW256`을 주지 않아 0번·255번
  항목이 검은색·흰색으로 고정됩니다. `game.pal`의 0번은 마젠타(컬러키 색)인데, 이 때문에 모든 마젠타
  픽셀과 컬러키 0xFF00FF가 11번(254,2,254)으로 매칭됩니다. 팔레트가 다른 `icon.bmp`의 배경
  (248,8,248)도 11번이 되어 투명해집니다. 이것을 재현하지 않으면 타이틀의 칼 커서에 분홍 상자가 생깁니다.
* 팔레트 페이드(0x40b350/0x40b450)는 `gfx+0x21c`에 보관된 원본 팔레트에서 매 프레임 계산.

### 사운드 / 음악

* 효과음 16개 (`sound/*.wav`) → DirectSound 정적 버퍼, 재생 = `SetCurrentPosition(0)` + `Play(0)`.
* 음악: DirectMusic 세그먼트 슬롯 20개.
  * 第一幕/とことん: `sound/bgm.mid` (120 PPQ), 루프 0–139000 MUSIC_TIME (= 0–85.51초)
  * 第二幕: `data/000.dat` (실제로는 MIDI, 960 PPQ), 루프 31488–238848 (= 20.5–155.5초)
  * 반복 횟수 0xFFFF.
* 포트의 시퀀서는 DirectMusic MIDI 임포터처럼 음표를 (시작, 길이)로 바꿔, 루프 지점에 걸친 음표도
  끝까지 울리게 합니다.

### 입력 (0x411f70-0x412400)

* 장치 0 = 키보드(`GetKeyboardState`), 장치 1 = 조이스틱(`joyGetPosEx`, 축 임계값 = 범위의 1/3·2/3).
* 가상 버튼 64개, 각 버튼에 (장치, 코드) 바인딩 목록 (0x40b5f0에서 등록).
* 상태 버퍼 2개(0x4200c0, 0x4201bf — 255바이트 간격)를 매 프레임 교대, `pressed` = 이번에 눌림 & 이전에 안 눌림.

| 버튼 | 키보드 | 조이스틱 | 의미 |
|---|---|---|---|
| 1/3 | ↑/↓ | 상/하 | 메뉴 커서 |
| 2/4 | ←/→ | 좌/우 | 레인 이동, 모드 전환 |
| 5 | Z | 버튼1 | 베기 |
| 6 | ↑ | 상 | 점프 |
| 7 | ↓ | 하, 버튼3 | 방어 |
| 8 | X | 버튼2 | 필살기 |
| 9 | Z | 버튼1 | 결정 |
| 10 | Esc | | 종료 |
| 11 | Tab | | 리플레이 빨리 감기 |

### 메인 루프 (0x40bf50)

`timeGetTime` 기준 16/17/17ms 간격(평균 60fps). 10ms 이상 밀리면 그리기를 한 프레임 걸러 생략
(프레임 스킵), 500ms 이상 밀리면 기준 시각을 리셋. 빨리 감기 중에는 씬 함수를 그리기 없이 3번 더 호출.

### 씬 (0x41f798 = ID, 0x41f79c = 함수 포인터)

| ID | 함수 | 내용 |
|---|---|---|
| 0 | 0x40c050 | 타이틀 진입 |
| 1 | 0x40c080 | 타이틀 (시작 / 랭킹, 모드 선택) |
| 2 | 0x40d560 | 第一幕 플레이 (리플레이 기록) |
| 3 | 0x40e840 | 第二幕 플레이 |
| 4 | 0x40f420 | とことん 플레이 |
| 5/6/7 | 0x40e2d0 / 0x40ef60 / 0x40f850 | 각 모드 리플레이 재생 |
| 8 | 0x40df30 | 결과 화면 |
| 9/10/11 | 0x40c4a0 / 0x40ca00 / 0x40cf10 | 각 모드 랭킹·리플레이 목록 |

게임 상태 구조체는 0x41f688 (함수 0x40b5e0이 주소를 반환): +0 카메라 X, +8 카메라 Y, +0x10 점수,
+0x14 점수 배율, +0x18 콤보, +0x1c 필살기 게이지, +0x3c 점수 상한, +0x40 현재 건물 태스크,
+0x44 플레이어 태스크 등 (`docs/notes/part_*.md`).

## 파일 형식 (모두 리틀 엔디언)

* `save/replay<N>.rep`: `u32 난수 시드`, `i32 개수`, `개수 × {i32 프레임, u8 버튼, u8[3] 패딩}`.
  매 프레임 눌려 있는 버튼을 6,7,5,8,2,4,9 순서로 기록. 재생 시 같은 시드로 `srand` 후 입력을 주입.
  1–10 = 第一幕, 11–20 = 第二幕, 21–30 = とことん.
* `save/score.sav`, `daini_score.sav`, `endless_score.sav`: 80바이트, `10 × {i32 최대 콤보, i32 점수}` (높은 순).
* `save/game.sav`: `i32 해금 단계` (0 = 第一幕만, 1 = 第二幕, 2 = とことん).
  원본에는 플레이 시간을 같은 파일에 쓰려다 `"rb"`로 열어서 실패하는 버그가 있고, 포트도 그대로 재현합니다.
* `data/023.dat`, `024.dat`: 스토리·스태프롤 텍스트. 0x20 이상 바이트를 `^ 0x3A`로 복호화 (0xFF는 0xC5).

## 결정론 재현에서 주의한 점

* `rand()`: MSVC LCG (`seed = seed * 214013 + 2531011; return (seed >> 16) & 0x7fff`), 호출 순서도 원본 그대로.
* x87 FPU는 MSVC 기본 53비트 정밀도로 동작 → 모든 식을 `double`로 계산하고 원본이 `fstp dword`로
  저장하는 지점에서만 `float`로 반올림하면 SSE2와 결과가 같습니다. `_ftol` = 0 방향 버림.
* 정수 오버플로는 32비트 순환(`-fwrapv`), FMA 축약 금지(`-ffp-contract=off`).
* 원본이 초기화하지 않은 스택 값을 복사하는 곳은 0으로 채움 (그 값을 읽는 코드는 없음).
